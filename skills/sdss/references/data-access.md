# Interfaces and bounds

Official starting points:

- [DR20 data access](https://www.sdss.org/dr20/data_access/) and [getting data](https://www.sdss.org/dr20/data_access/get_data/): catalog services, per-object spectra and bulk alternatives.
- [ALLSPEC schema and joins](https://www.sdss.org/dr20/data_access/allspec/) and [official ALLSPEC notebook](https://github.com/sdss/dr20_tutorials/blob/main/allspec.ipynb): DR20 ALLSPEC 1.0.2 assembles pipeline records from DR8 through DR20. One row is a spectral product, not one unique object.
- [DR20 imaging](https://www.sdss.org/dr20/imaging/): no new or updated SDSS imaging; use legacy imaging documentation.
- [Valis and Zora](https://www.sdss.org/dr20/data_access/zora_and_valis/): official SDSS-V name, cone and sdss_id discovery, metadata and spectral API. Valis has a different target-based scope; do not silently substitute it for an ALLSPEC query.

The helper calls public `https://skyserver.sdss.org/dr20/SkyServerWS/SearchTools/SqlSearch?format=json&cmd=...`. It uses `dbo.fGetNearbyAllspecEq(ra,dec,radius)` with radius in arcminutes, joined to `allspec` by `allspec_id`. Coordinates use the server's spherical cone implementation, including wrap and poles. Numeric identifiers are cast to varchar before JSON serialization; modern specobjid values can exceed 64 bits.

Classification/redshift joins are intentionally limited: BOSS v6_2_1 daily records join `spAll` by specobjid; legacy optical records join `SpecObjAll`. Other ALLSPEC products remain discoverable with their metadata and archive URL, but the helper supplies no inferred parameters for APOGEE, MaNGA or other coadds. Null joined fields do not mean no physical properties or archive spectra. For full stellar analysis use the appropriate Astra/APOGEE products and caveats; for IFU science use MaNGA/LVM documentation.

`photo-cone` and `photo-id` call the DR17 SQL endpoint and select `PhotoObjAll` measurements. Cone searches require mode=1 (primary); exact-ID queries retain the record's mode. They expose only r-band PSF and cModel magnitudes, their uncertainties, extinction, clean flag, morphology code and exact legacy specObjID association. No cross-release positional association is asserted.

Helper bounds are local operational choices, not survey coverage or provider limits: one request per catalog command, radius greater than zero and at most 60 arcminutes, 1–1000 returned rows (default 100, plus one lookahead), 2 MB catalog/path-resolution response, 1–120 second timeout (default 30), and 16 MB default spectrum download (adjustable up to 50 MB). Spectrum commands re-query the exact record and download one file; Valis delivery also resolves one product path. The socket timeout applies to blocking operations; a total read deadline is checked between chunks, so a final blocking read may run up to another socket timeout. There are no automatic retries. Exit 1 and JSON `status:error` distinguish failure from empty results; argument syntax errors use argparse's exit 2 and stderr.

Both cone and target searches paginate by ascending ALLSPEC ID; photometric cones paginate by numeric objID. Use `next_after` only with identical coordinates, namespace, identifier and filters. The last lookahead row is not consumed until the next page. This is not a snapshot transaction: provider changes between pages can change results. Stop at a deliberate page/row budget and report incompleteness. `photo-id` returns an exact row and needs no paging.

The linked official documentation does not specify a numeric public request-rate guarantee. Query sequentially, cache outputs for the task, avoid repeated broad cones, and stop on timeout, HTTP 429 or service failures. For bulk or long-running work use official CASJobs/SciServer or SAS bulk workflows rather than increasing loop concurrency.

`spectrum` re-queries the exact ALLSPEC ID and uses its `sas_url`, not a guessed filename. It accepts HTTPS SAS FITS/FITS.gz paths on `data.sdss.org`, `dr20.sdss.org` and `dr17.sdss.org` for DR17/DR20. It refuses redirects and other archive layouts so a changed interface requires inspection. Download bounds apply to declared and actual bytes; the destination must not exist. The output manifest retains the exact observation and reduction provenance. HTTP availability does not establish scientific validity.

`--delivery valis` is an alternative official delivery service with a supported scope of DR20 BOSS v6_2_1 daily lite FITS. The helper extracts field, MJD and catalogid as exact strings from the catalog SAS path, checks their agreement with the record, then calls `https://api.sdss.org/valis/paths/specLite` with `release=DR20` and repeated `kwargs` arguments. It requires `exists=true` and the returned official archive URL path to equal the original SAS path before calling `/valis/file/specLite/download` with the same arguments. See the [deployed Valis schema](https://api.sdss.org/valis/openapi.json), [interactive documentation](https://api.sdss.org/valis/docs) and [official file-route implementation](https://github.com/sdss/valis/blob/main/python/valis/routes/files.py). The download returns the original archive file, not reserialized spectrum arrays. Both delivery modes retain normal certificate verification and reject redirects; they do not automatically retry or switch services. Valis delivery refuses other product templates. Keep the archive URL and delivery URL separately in the manifest.
