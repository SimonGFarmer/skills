# Source access and limits

Fresh installations can read public [USGS GeoJSON feeds](https://earthquake.usgs.gov/earthquakes/feed/v1.0/geojson.php), [FDSN catalog count/query](https://earthquake.usgs.gov/fdsnws/event/1/), and available content linked from [GeoJSON event detail](https://earthquake.usgs.gov/earthquakes/feed/v1.0/geojson_detail.php). There is no account, paid tier, credential or bundled catalog. HTTPS/DNS/TLS access to `earthquake.usgs.gov` and Python 3.11+ are sufficient for the helper. A project may separately need maintained readers for downloaded products. Availability and network policies can change; successful access to one event does not guarantee all products or future uptime.

| Interface | Useful access | Contract |
| --- | --- | --- |
| `/earthquakes/feed/v1.0/summary/LEVEL_WINDOW.geojson` | Recent snapshots | Levels `all`, `1.0`, `2.5`, `4.5`, `significant`; windows `hour`, `day`, `week`, `month` correspond to past hour/day/7 days/30 days. Generated every minute. |
| `/fdsnws/event/1/count` | Check fixed query size | Same filters as query; helper requests plain-text integer. |
| `/fdsnws/event/1/query` | History/custom region or exact event | Set format explicitly (`geojson` or `csv` here). API defaults otherwise include a rolling 30-day start and current end; helper requires both times for regional queries. |
| `/fdsnws/event/1/application.json`, `/catalogs`, `/contributors` | Discover supported values/sources | Official enumerations; do not treat an old catalog availability table as live coverage. |
| Exact event `properties.products` | Discover files | Each event has different product types and content keys. Follow actual `contents` URLs, never construct filenames from assumptions. |

API times are ISO8601; USGS assumes UTC when a timezone is omitted, while the helper requires explicit `Z` or an offset and normalizes UTC. API start/end are inclusive. Adjacent intervals may repeat boundary events. A date-line box may use longitude outside [-180,180], within the API's [-360,360] range: e.g. `--bbox 170 -20 190 20`. Circle radius is km, not degrees; the helper deliberately permits one circle or one box, not their intersection.

Service maximum is 20,000 results; requests over it can fail with HTTP 400. Offset is one-based; `orderby=time-asc` is supported. Helper preflight rejects >20,000, a page is 1..1,000 (default 100), and one explicit interval is at most 366 days. These helper bounds are workload choices, not limits of historical USGS coverage. Refine/split larger searches, retain fixed end and filters, and track your total budget. Paging order does not resolve equal-time ties or freeze a changing catalog. Count and query are separate requests; `count_at_preflight`, `next_offset` and `has_more_at_preflight` may drift with revisions. Fetch small complete partitions when reproducibility matters, deduplicate IDs, and keep the original response and manifest. Do not claim all requested records when stopping at a budget, empty page after a positive count, or any failed page.

Feeds are recent views, not immutable history. Historical catalog values also receive corrections. `updatedafter` selects changes within the origin-time/region filters; it is not a complete change stream and the helper does not retrieve deletion tombstones. A record leaving a feed is not necessarily deleted. For synchronization, separately investigate `includedeleted` (GeoJSON/CSV), HTTP 409 for deleted event requests, and `includesuperseded` for exact-event version history, documented in the API. Neither a local download nor `reviewed` status promises finality.

[ComCat](https://earthquake.usgs.gov/data/comcat/) aggregates many networks. Coverage varies by region, time and magnitude; [availability tables](https://earthquake.usgs.gov/data/comcat/availability.php) are dated source summaries. Do not infer a common completeness threshold or uniform measurement method from a global plot.

Every request caps the response at 8 MB (count at 1 KB); product default cap is 5 MB, maximum 50 MB. Request timeout defaults to 30 seconds, configurable up to 60; socket operations are timed and a monotonic deadline is checked between reads. There are no automatic retries, background polling or fallback fixtures. Standard rolling applications should cache/reuse the feed instead of repeatedly querying the catalog; avoid polling more often than the feed's minute updates. No universal service rate allowance is promised here.

HTTP 204 means no returned catalog data. Invalid bounds fail locally before network access. HTTP 400 calls for query refinement/parameter review; 404 for unavailable event/content; 409 for deleted-event conflict; 429 for waiting before a deliberate retry. Timeout/TLS, 5xx, invalid JSON/CSV, unexpected schema, size mismatch, changed product version and unsupported content hosts fail visibly. Processing errors use JSON stderr with exit status 2; argument syntax errors use argparse's usage text and exit 2. Stdout is a result only after successful processing. JSON uses ASCII escapes so output is also valid UTF-8 on default Windows encodings. Product writes are complete-file, do not overwrite a destination, and need filesystem hard-link support in that destination directory. Preserve failures as failures, never as empty scientific evidence.
