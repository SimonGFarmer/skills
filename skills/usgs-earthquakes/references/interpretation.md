# Measurement and product interpretation

Retain the raw event beside normalized fields. [GeoJSON summary](https://earthquake.usgs.gov/earthquakes/feed/v1.0/geojson.php) carries preferred event measurements and IDs; [CSV](https://earthquake.usgs.gov/earthquakes/feed/v1.0/csv.php) includes magnitude/location sources and available error columns. Not every format contains every quantity.

| Value | Interpretation |
| --- | --- |
| GeoJSON `id`; CSV `id` | String event identifier. `net` + `code` denotes a contributor's identifier; `ids` lists aliases. Event association/preference may change the canonical ID. Match aliases when tracking revisions; never use list position or rounded coordinates as identity. |
| `time`, `updated`, feed `metadata.generated` | GeoJSON epoch **milliseconds**: origin, record update and feed generation respectively. CSV uses ISO timestamps. Retrieval time is a fourth time recorded by the helper; product `updateTime` identifies its version. |
| `geometry.coordinates` | `[longitude, latitude, depth]`: decimal degrees, decimal degrees, km positive downward. Depth is hypocentral depth, not elevation or epicentral distance. Preserve negative and missing depth. When converting to altitude meters explicitly use `-1000 * depth_km`; label any vertical exaggeration separately. |
| `mag`, `magType` | Dimensionless magnitude estimate and method (e.g. `ml`, `mb`, `mw`, `mww`). Different methods have different applicability; do not relabel every value as Mw. Magnitude is not intensity, linear size or energy in joules. Negative/zero magnitudes are valid; absent magnitude is unknown. |
| `type`, `status` | Event category and processing/review status. Not every record is an earthquake. Reviewed does not mean error-free, immutable or equivalent confidence across networks. |
| CSV `horizontalError`, `depthError`, `magError`, `magNst` | Reported horizontal/depth errors in km, magnitude error in magnitude units, and station count used for magnitude. Missing columns/blank values remain unknown; zero stays zero. Read the originating solution's uncertainty definition/confidence level before treating these as comparable statistical intervals. Do not invent a universal confidence ellipse from a scalar error. |
| `rms`, `gap`, `dmin`, `nst` | Travel-time residual seconds, azimuthal gap degrees, nearest-station distance in degrees, and station counts are diagnostic context rather than interchangeable uncertainties or one confidence score. Do not convert `dmin` directly to km without stating an angular-distance model. |
| `cdi`, `mmi`, `felt`, `alert`, `tsunami` | Community/instrumental-model intensity and response/impact metadata differ from magnitude. `tsunami` is a processing flag, not proof of a tsunami or a warning decision. Missing PAGER alert does not mean no impact. |

Uncertainty is solution-specific. Origin products may retain contributor-specific string fields such as `horizontal-error`, `vertical-error`, `magnitude-error`, `depth-type`, `review-status` and `quakeml-origin-publicid`. The helper exposes them without rewriting their meaning. Inspect the actual [QuakeML specification](https://quake.ethz.ch/quakeml/) and contributor metadata when interpreting confidence levels, fixed depths, multiple magnitudes or origins. QuakeML uses meters for origin depth quantities: do not reuse the GeoJSON km assumption when reading XML. FDSN documentation says `includearrivals` is currently unimplemented; do not promise phase picks from that flag. Available `phase-data` content is a separate product.

[Product preference](https://earthquake.usgs.gov/data/comcat/products.php) is by highest `preferredWeight`, then most recent `updateTime` for a tie, within a product type. Newest alone may select a different contributor's less preferred estimate. Source/type/code/update time identify an exact version. The inventory's `preferred_in_response` considers active (`UPDATE`) products in that response. Exact product downloads refuse an unavailable version; discovering a later version does not authorize silently substituting it. Separate historical versions require the API's superseded-product mode, outside this helper.

[Product types](https://earthquake.usgs.gov/data/products/) have different meanings: `origin` source estimates; `phase-data` station picks/amplitudes; `moment-tensor`/`focal-mechanism` solutions; `shakemap` measured/interpolated shaking; `dyfi` crowdsourced intensity; `losspager` impact estimates. Availability is event-specific. ShakeMap grid units and uncertainty belong to that product's own schema; do not interpret grid cell values as earthquake magnitude or assume all shaking is observed at stations. Raw download support is not scientific decoding support.

For derived maps/animations, label catalog selection, thresholds, projection, depth scaling, and illustrative motion. Temporal clustering does not prove causality or identify which fault plane ruptured. Show query/retrieval/update provenance and a completeness caveat alongside comparisons. This skill supplies scientific data access, not earthquake prediction or operational warnings.
